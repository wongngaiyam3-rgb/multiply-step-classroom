# 雪林數學小屋

小四數學自習網站。學生在 iPad 或電腦選擇 4A、4B、4C 及 1–25 號後開始。每次開新一回由伺服器抽十題，同一回合內題目不重複。

## 網址及切換版本

| 版本 | 網址參數 | 出題方式 |
| --- | --- | --- |
| 乘法（預設） | `?mode=mul` | 每回五題兩位數乘兩位數、五題三位數乘兩位數。 |
| 除法 | `?mode=div` | 兩位數或三位數除以兩位數，每題均可整除。 |
| 倍數 | `?mode=multiple` | 從四個選項辨認指定數的倍數。 |
| 因數 | `?mode=factor` | 從四個選項辨認指定數的因數。 |

網站發佈在 GitHub Pages 的 `multiply-step-classroom/sakura-math/`。在網址後加入上表參數即可預選練習。學生也可在首頁切換。獨立測試可加入 `?demo=1`。示範使用記憶體資料，每次重新載入便清空，適合試做及投影演示。

## 檔案分工

| 檔案 | 用途 |
| --- | --- |
| `index.html` | 學生入口、主要導覽及教師入口。 |
| `style.css` | 北歐配色、觸控版面、首頁及答題飄雪、完成動畫，支援系統減少動態效果設定。 |
| `nordic-winter.svg` | 原創北歐雪地、木屋及小狐狸主圖，內嵌 WebP。 |
| `app.js` | 班別學號、題目介面、逐題回饋、計時、成績、排行榜，以及教師查閱與 CSV。 |
| `config.js` | Supabase API 網址及可公開的 publishable key。 |
| `supabase/schema.sql` | 獨立資料表、伺服器出題、計分、答題與教師權限。 |
| `supabase/ranking.sql` | 將各裝置的已提交題數按班別和學號合併，產生公開排行榜代號。 |

發佈版本的網頁檔案直接放在 GitHub 上 `sakura-math/`，沿用現有 Pages 的 `main` 根目錄部署。這個版本毋須安裝 JavaScript 套件或執行建置指令。若另建 GitHub 儲存庫，可將網站前端檔案放在根目錄，再在 **Settings → Pages** 選擇由 `main` 的根目錄發佈。

## 學生紀錄及計分

- 每題提交後即寫入 Supabase，記下題目、作答、正確答案、對錯、逐題及累計用時。伺服器在同一回合鎖定題序並避免重複計分。連線失敗時原答案保留在畫面，學生可重試。
- 做完十題可查看本回分數、總用時及每題訂正。個人紀錄也會列出已回答部分題目的未完成回合。
- 排行榜按完成題數降序排列，每提交一題即累加一題。同分並列，可按練習模式篩選。排行榜顯示隨機代號和累計題數。班別、學號及作答資料由教師平台查閱。
- 每部瀏覽器透過本機資料記住班別和學號對應的學生取回碼。學生更換裝置時，可先在舊裝置的「練習紀錄」抄下取回碼，再在新裝置輸入原班別、學號及取回碼。沒有帶取回碼的另一部裝置會開啟新的個人紀錄，排行榜仍按班別及學號合計。共用 iPad 上，班別和學號用於辨認學生，知道同一套選項的人可以開啟這部 iPad 已保存的該學生紀錄。

## 教師平台

1. 在同一 Supabase 專案的 **Authentication → Users** 建立或選擇教師的電郵帳戶，抄下其使用者 UUID。
2. 在 SQL Editor 執行以下指令，把指定帳戶加入本網站的教師名單。

```sql
insert into sakura_math.teachers(user_id)
values ('把這段換成教師使用者 UUID')
on conflict do nothing;
```

3. 在網頁底部按「教師入口」，以該帳戶登入。可逐回展開學生答案，或匯出 UTF-8 逐題 CSV。

教師白名單由伺服器檢查。學生原始資料保存在啟用 RLS 的獨立 schema。教師密碼、後端金鑰和學生作答紀錄均存放在 GitHub 原始碼以外。

## 改題或另作新版本

沿用現有四個模式時，只需更換派給學生的網址參數。要調整題型或難度，在 `public.sakura_start` 對應模式修改數字範圍、題目、正確答案與選項，再以遷移更新 Supabase。同步修改 `app.js` 中的模式描述及示範題。新增主題時也要更新資料表的模式限制。現有回合已保存當時的原題和答案。

若移到另一個 Supabase 專案，依序執行 `schema.sql`、`ranking.sql`，再填寫新的 `config.js` 和授權教師帳戶。
